## UI 修复

- `GIS_agent/front_end/src/Basemap.jsx`：启动不再预先加载完整 OSM 瓦片；简洁底图失败时也不自动切换。提供 `Retry simplified basemap` 和明确选择备用底图的按钮。
- `GIS_agent/front_end/src/mapDomExport.js`：复制当前 DOM/SVG 整饰的计算样式和屏幕位置，以两倍分辨率输出。标题换行、图例、定位符号、学校图标、比例尺、坐标和来源不再由另一套 Canvas 代码重新排版。
- `GIS_agent/front_end/src/mapExport.js`：继续按地图屏幕位置组合实际底图和 Leaflet 几何，再叠加共享整饰快照；未加载或失败的底图不能导出。
- `GIS_agent/front_end/src/App.css`：移除预览额外灰色内边距，避免同一地图在预览中缩小。

浏览器中首次简洁底图遇到一次瓦片 502；失败状态检查到 **0 个 `.leaflet-tile`**，没有偷偷加载完整 OSM。显式选择 OSM 后可以导出；后续简洁矢量底图也加载成功，多图层和缓冲区等导出使用简洁底图。交互与 PNG 对比检查了长标题换行、分组图例、学校图标和中心光晕。缩放按钮、弹窗及临时加载提示有意不进入 PNG。

## 待处理问题与边界

1. 第 9 例只读诊断：官方 `lcsd_rcd_1629267205214_38344/MapServer/WFSServer` 的 GetCapabilities 返回根节点 `{http://www.w3.org/1999/xhtml}html`，不是 WFS 文档。不能据此断言该数据源真的存在多个图层；当前后端提示需进一步区分 HTML/异常响应和真实不兼容。
2. 第 10 例确认缺少预期 `numberMatched` 导致失败；本次没有取得并核对完整响应，不能确认是服务变动、临时故障还是解析假设不兼容。需要单独修复 CSDI 响应校验并在官方服务恢复正常后复测。
3. 简洁底图仍依赖外网，UI 修复不保证外部瓦片服务可用。失败会保留提示，不把完整底图伪装为简洁底图。
4. 浏览器窄视口下，长标题和较长图例仍可能争夺地图空间；本次统一了两种视图的排版来源，没有全面重设计移动端布局。
5. 本轮属于功能与导出链路验收，不是 ArcGIS Pro 数值对照、跨浏览器兼容性或并发压力测试。驾驶覆盖为恒速路网估算，不代表真实救护响应时间。

## 后续：CSDI 响应处理修复

上述是 UI 验收当时的状态。随后针对两个 CSDI 错误修改了后端：

- 实际只读响应确认：官方 ArcGIS Web Adaptor 返回 HTTP 200 的 HTML 错误页，正文为 `Could not access any server machines`。直连和已有代理均返回错误页。
- `tools/csdi_sources.py` 在认定请求成功前校验 WFS 响应。HTML 错误页走最多三次退避/线路重试，失败后返回服务不可用；只有真正的 WFS 能力文档才会进入图层数量检查。
- hits 验证根节点及 `numberMatched`，缺失、unknown 或非法值不会引起 KeyError，也不会猜成零。GeoJSON 页面及 OGC 异常同样校验。失败不替换已有快照。
- `tools/csdi_tools.py` 返回独立的 `CSDI_SERVICE_UNAVAILABLE`，避免把上游故障描述成数据集不兼容。
- 新增 10 项回归测试，后端总计 **92 项通过**，覆盖错误页重试上限、线路恢复、快照保留、非法计数和正常恢复下载。
- 联网重跑 `csdi_map`（羽毛球场）和 `csdi_nearby`（指定健身室 500 米救护站查询），均正确返回 `CSDI_SERVICE_UNAVAILABLE`；官方仍返回错误页，未下载新快照。因此第 9–10 例的成功制图验收仍待官方服务恢复，不能改记为通过。
